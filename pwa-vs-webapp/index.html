PWA vs Standard Web App

透過這個概念驗證（Proof of Concept），親身體驗漸進式網頁應用（PWA）與傳統 Web App 的核心區別。

Standard Web App

傳統的網頁應用程式。依賴瀏覽器環境運行，需要網路連線才能讀取和使用。

  • ✕ 離線運作 (Offline Support)
  • ✕ 安裝至桌面 (Installable)
  • ✕ 獨立視窗運行 (Standalone Mode)
  • ✓ 響應式設計 (Responsive UI)
  • ✕ 背景服務線程 (Service Worker)
開啟 Standard Web App

Progressive Web App (PWA)

漸進式網頁應用。結合網頁與原生 App 的優勢，提供離線可用、可安裝以及無瀏覽器外框的體驗。

  • ✓ 離線運作 (Offline Support)
  • ✓ 安裝至桌面 (Installable)
  • ✓ 獨立視窗運行 (Standalone Mode)
  • ✓ 響應式設計 (Responsive UI)
  • ✓ 背景服務線程 (Service Worker)

💡 如何進行測試與觀察區別？

  1. 步驟一：點擊上方按鈕開啟兩個應用程式
    請分別在獨立的瀏覽器分頁中打開「Standard Web App」與「PWA 應用程式」。
  2. 步驟二：體驗安裝功能 (PWA 專屬)
    在 PWA 網頁的右上方，你會看到一個「安裝此 App」的按鈕（或者瀏覽器網址列右側會出現安裝圖示）。點擊它，這將會把 PWA 安裝至你的電腦/手機，並且它會以獨立的無邊框視窗開啟，看起來就像原生應用程式一樣！
  3. 步驟三：模擬離線狀態 (核心測試)
    在兩個應用程式的網頁上，按下鍵盤的 F12 打開開發者工具。切換到 Network (網路) 標籤頁，將狀態從 Online 改為 Offline (離線)。
  4. 步驟四：重新整理頁面 (F5)
    - Standard Web App：會出現瀏覽器的「無法連線至網際網路」錯誤畫面。
    - PWA 應用程式：頁面會照常順暢載入！你可以繼續新增、刪除待辦事項，甚至關閉分頁再重新開啟，一切依舊正常運作。

🔍 技術架構細節對比

特點 Standard Web App Progressive Web App (PWA)
進入管道 瀏覽器網址列輸入 URL 可從 URL 進入，也可像原生 App 從桌面圖示啟動
快取機制 標準 HTTP 瀏覽器快取 (容易因離線或快取過期失效) Service Worker Cache Storage (完全由程式控制，離線必備)
設定檔文件 無特別要求 必須具備 manifest.json (定義圖示、顏色、顯示模式)
執行緒環境 單一主執行緒 (UI Thread) 擁有 Service Worker 背景獨立執行緒，可處理快取攔截、推送通知等
離線資料讀寫 雖然能用 LocalStorage，但若網頁本身打不開就毫無意義 即使完全斷網，頁面結構 (App Shell) 照樣載入，並搭配 LocalStorage 實現離線操作
安全要求 HTTP 或 HTTPS 皆可 必須使用 HTTPS（本機開發測試 localhost 除外）才能啟用 Service Worker
