1. Atomic Instructions in Firmware vs. Hardware (LR/SC & AMO)

          
Why Naive Locks Fail: With regular lw and sw, both Core 0 and Core 1 can read LOCK == 0 in MESI S (Shared) state simultaneously. Their subsequent sw 1 instructions enter their respective Store Buffers without preventing the other core from also entering the critical section (demonstrated in Demo 2 Phase 1).

          
    
            
  • RISC-V lr.w / sc.w (Load-Reserved / Store-Conditional):
              
      
                
    • HW Requirement 1: Per-core res_valid and res_addr Reservation Register. lr.w sets res_valid = 1, res_addr = addr.
      • 
                
    • HW Requirement 2 (Cache Snoop Integration): When the peer core issues BusUpgr or BusRdX to res_addr, the hardware snoop controller automatically clears res_valid = 0!
      • 
                
    • HW Requirement 3: sc.w checks res_valid before writing. Only the first core to win the MESI bus succeeds (rd = 0); the losing core sees res_valid == 0, aborts its write, gets rd = 1, and loops back in FW!
      • 
              
    
            
    • 
            
  • RISC-V amoswap.w / amoadd.w (Atomic Memory Operations):
              
      
                
    • Drains the local Store Buffer, acquires the cache line in M (Modified) state via BusRdX/BusUpgr, and performs an indivisible Read-Modify-Write in a single atomic L1 phase so no snoop can intervene between the read and write.
      •

2. CPU → Store Buffer → L1 Cache & Store-to-Load Forwarding

          
Writing directly to L1 Cache on every sw would stall the CPU pipeline whenever L1 misses or needs a BusUpgr to invalidate other cores.

          
    
            
  • Store Buffer Enqueue: sw writes (addr, data) into the 4-entry FIFO Store Buffer in 1 cycle and retires immediately.
    • 
            
  • Store-to-Load Forwarding (Demo 1 Cycle 18): When a subsequent lw on the same core accesses an address currently still in the Store Buffer, the Store Buffer comparator forwards the latest data directly to the CPU register in 1 cycle without waiting for L1!
    • 
            
  • Store Buffer Drain: In the background, the oldest Store Buffer entry (SB[0]) drains to L1 Cache. If L1 holds E or M, it drains in 1 cycle; if L1 holds S or I, L1 issues BusUpgr or BusRdX on the coherence bus.
    • 
          

        


        

          
3. Cache-to-Cache Communication: MESI Snooping Protocol

          
Each L1 Cache line holds a 2-bit state: M (Modified), E (Exclusive), S (Shared), or I (Invalid).

          
    
            
  • I → E (Exclusive Read): Core 0 reads 0x1000 (`BusRd`). Peer Core 1 does not have it (`Snoop MISS`), so Core 0 enters E state. Subsequent write upgrades E → M silently with zero bus traffic!
    • 
            
  • M → S (Dirty Snoop Flush / Intervention, Demo 1 Cycle 40): Core 1 reads 0x1000 (`BusRd`) while Core 0 holds modified data in M state (and RAM is stale). Core 0 snoops BusRd, flushes the dirty word onto the bus & RAM, and both cores transition to S.
    • 
            
  • S → M & Peer S → I (`BusUpgr`, Demo 1 Cycle 49): Core 1 writes to a S line, broadcasting BusUpgr. Core 0 snoops it and invalidates its copy (S → I), while Core 1 becomes M.
    • 
          

        


        

          
4. CPU Instruction Reordering (ROB Out-of-Order & Store-Load Reordering)

          
Demonstrated in Demo 3 across two hardware layers:

          
    
            
  • Pipeline Out-of-Order Execution (4-Entry ROB, Demo 3 Phase 1): When ROB[0] is a slow lw stalled on an L1 Cache Miss (MEM_WAIT), dependent instructions stall in WAIT_DEP (RAW hazard), while younger independent ALU instructions and L1-Hit loads execute Out-of-Order (OOO_DONE) ahead of ROB[0]!
    • 
            
  • Store-Load Memory Reordering (Litmus Test, Demo 3 Phase 2 vs Phase 3): Core 0 executes X=1; r0=Y while Core 1 executes Y=1; r1=X. Without fence, X=1 and Y=1 sit in each core's Store Buffer while the younger lw instructions bypass the Store Buffer and hit S state (reading 0) in L1 Cache—resulting in r0 == 0 && r1 == 0! Adding fence rw, rw stalls the lw until the Store Buffer drains to L1, guaranteeing sequential consistency.
